# Offline reliability benchmark

**25 of 25 synthetic regression scenarios passed on the submission working tree.** The same scenarios passed 20 of 25 before the reliability patch, as recorded during implementation. This review reproduced the current result and inspected the returned claim reports. It did not reconstruct the pre-patch working tree.

## Reproduce

From the repository root, with Python installed:

```powershell
python -B -m benchmarks.final_offline
python -B -m unittest discover -s tests -p test_reliability_hardening.py -v
```

The first command emits per-case expected and actual verdicts and exits nonzero on a mismatch. The second runs the same cases plus checks for request-local reuse, Java LTS evidence and malformed quote references. Neither constructs live provider clients.

## Results

| Measure | Observed offline |
| --- | --- |
| Scenario pass rate | **25/25 (100%)** |
| Final claim verdicts | 9 outdated, 2 supported, 16 uncertain, 2 not checked |
| Unsupported decisive verdicts | **0 of 11** by the fixture labels and evidence checks below |
| Adverse decisive model proposals | **9 of 9** became uncertain and had no accepted citations |
| Mixed-claim scenarios | **5 of 5** matched every expected verdict and both expected scores |

The review inspected the returned claims in addition to the benchmark's pass flags. Each of the 11 decisive verdicts matched the case label, had accepted citation IDs and quotes, and passed the deterministic version check. Each quote was a literal substring of its identified source. The denominator is confined to these scripted inputs.

The nine adverse proposals tested an old release page offered as proof of current status, a third-party citation, a fabricated quote, an unknown source ID, an unsupported correction, a conflict, a missing date, a preview release and a future-dated release. For the fabricated quote, unknown ID and unsupported correction, the verifier returned distinct validation errors and cleared the accepted citation and quote arrays. The irrelevant Java result was filtered before judgment, leaving only the extraction call. The absent-source case abstained separately without a decisive proposal to reject.

| Mixed case | Claim verdicts in input order | Evidence coverage | Freshness |
| --- | --- | --- | --- |
| Independent same-entity evidence | Outdated, supported | 100% | 50% |
| One claim lacks evidence | Outdated, uncertain | 50% | 0% |
| Current claim plus historical release date | Outdated, not checked | 100% | 0% |
| Rate limit on first judgment | Uncertain, uncertain | 0% | Not assessed |
| Two separate official pages needed | Outdated, outdated | 100% | 0% |

Citation IDs are local to each claim. Two claims can each cite an `s1` without sharing a source. The two-page case also asserted two retrieval calls. The rate-limit case asserted one search, while the extraction-rate-limit case asserted no claims or searches. The timeout case required a report status of `unavailable` with an uncertain claim.

## What the benchmark actually exercises

[The case matrix and runner](../benchmarks/final_offline.py) script extraction output, search results, judgment proposals and fetched page text. They call the production `Verifier.verify()` in its default mode, so the strict release guards run. Claim grounding, search planning, result filtering and ranking, retrieval planning, citation and quote acceptance, deterministic version rules, failure handling and report scoring execute as production code. The dependency mocks skip HTTP transport, provider JSON parsing and real search/model behavior. Only the two-fetch case enables a page retriever, and its response is scripted. The ordinary case assertion checks verdict lists, both scores and selected call/status fields. The additional review above inspected citations directly.

No expected verdict is generated by the verifier. The case labels and checked statuses/call counts are declared in the matrix. Expected freshness and coverage are computed from those manual labels with arithmetic equivalent to the production formulas. Those assertions check consistency with the labels and formula. They provide no independent calibration. Several positive cases intentionally give the judge the same quote as the supplied source text. The historical control supplies a non-time-sensitive flag, so it tests downstream exclusion, with extraction classification already scripted. The set was chosen during development and is weighted toward release claims.
